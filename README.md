# AI 答辩压力舱

**把项目讲清楚，在一次次问答中发现问题、补充证据，再验证自己的改进。**

AI 答辩压力舱是一款面向项目答辩、毕业设计、创新创业和产品路演的训练工具。带着你的项目资料，与四位不同视角的 AI 评委交流，获得追问、回答反馈、诊断报告和下一步改进建议。

它既适合正式答辩前的演练，也可以帮助尚未成熟的项目梳理目标用户、技术方案与应用价值。

> 当前版本面向本机单用户使用。真实分析、问答和评分需要配置模型服务；AI 反馈属于训练建议，不是客观考试成绩。主动选择的模拟示例始终有明确标识，真实请求失败不会自动替换成模拟结果。

## 功能介绍

### 项目建档与资料管理

- 创建、编辑、搜索、归档和恢复项目，保留资料版本。
- 支持创新创业项目、大创项目、毕业设计、产品路演及其他类型。
- 未提交的表单和回答保留为浏览器草稿，正式记录由后端统一保存。
- 上传或拖入图片、PDF、UTF-8 TXT，预览材料，将提取文字核对后追加到项目字段。
- 通过本地中英文 OCR 识别图片和扫描 PDF 中的印刷文字。

### 项目分析与资料问答

- 根据项目资料生成核心价值、用户场景、优势、可行性、风险、证据缺口和推荐提问方向。
- 在项目资料库中建立原文索引，进行关键词检索和带引用的资料问答。
- 配置独立向量模型后使用语义检索或混合检索，让相关资料参与分析和追问。
- 保留原文片段、页码与来源，方便回看依据；检索命中不等于内容已经得到事实验证。

### 四位评委，多种看项目的角度

| 评委 | 关注点 | 希望帮助你想清楚的事 |
| --- | --- | --- |
| 商业评委 | 市场、商业模式、竞争与持续经营 | 谁需要它？价值如何兑现？ |
| 技术评委 | 技术实现、架构、安全与稳定性 | 方案做得出来吗？关键难点怎么解决？ |
| 用户评委 | 真实痛点、使用体验与差异化 | 用户为什么愿意使用和选择它？ |
| 魔鬼评委 | 逻辑漏洞、矛盾、假设与证据 | 哪些结论还站不住脚？怎样补上依据？ |

评委以通俗、引导式提问帮助你思考项目，每轮围绕一个具体问题展开。四个角色通过不同提示词调用模型，当前按轮次运行，不具备并行多 Agent 自主协作能力。

### 动态答辩与语音辅助

- 选择“项目梳理”或“答辩演练”，设置训练目标、评委与 5 / 10 题长度，沿用项目资料中选择的难度。
- 结合项目背景、最近对话和最新回答生成追问，支持中途切换评委。
- 卡住时可以请求提示，查看回答反馈，按议题逐步完善思路。
- 对话区支持 Enter 发送、Shift + Enter 换行、附件与 OCR、失败重试和结束确认。
- 通过会话地址恢复已保存的训练，请求失败时保留输入和重试入口。
- 配置语音服务后，录音转写、核对后加入回答草稿，或手动朗读评委的问题。

当前使用普通 JSON 请求，尚无流式输出。语音采用逐轮请求，尚不支持实时通话、打断对话或口语表现评分。

### 诊断报告与项目漏洞地图

- 查看回答优点、薄弱点、证据缺口、优先问题、原文依据和可执行建议。
- 从逻辑表达、数据与证据支撑、技术可行性、商业或应用价值、临场应变五个维度复盘。
- 已评估维度为 0～100 分；观察不足的维度显示原因，不用零分或估计分补齐。
- 新报告只有五维均已评估才计算综合分，采用五维等权平均；覆盖完整时展示能力雷达图。
- 风险地图支持缩放、移动、等级筛选与节点详情，展示来源、证据缺口和建议；连线表示共同依据，不表示已经证明的因果关系。

### 历史记录与持续改进

- 查看当时的资料、完整问答、评委和原始报告，不重新生成另一份历史评价。
- 将报告建议加入改进任务，记录状态、笔记和证据材料；“已完成”表示用户自行记录。
- 按历史薄弱点或选定任务重新训练，可选择原资料或当前项目版本。
- 每次复训创建新会话，保留原记录；使用实际保存的报告比较可比维度的变化。
- 导出历史记录与任务 JSON。导出不包含附件原文件，也不等于完整工作区备份。

## 开始一次训练

1. **配置模型**：进入“系统设置”，填写对话模型配置，测试连接后保存。
2. **创建项目**：填写资料，按需导入文档或上传图片，核对提取文字后保存。
3. **分析项目**：在详情页生成画像；开始训练时也会检查当前资料是否有匹配画像。
4. **开始交流**：确认资料、训练目标与评委，选择短程训练，结合问题逐轮回答。
5. **查看复盘**：结束后生成报告，回看原文依据与风险地图，挑选最需要解决的问题。
6. **改进并复训**：记录任务进展、更新项目，再开始新训练并比较结果。

无需一次填出“完美项目”。可以先保留草稿，逐步补齐资料；正式创建仍需满足页面上的必填校验。

## 快速搭建

### 环境要求

| 工具 | 要求 |
| --- | --- |
| Node.js | 22.15.0 或更高，需支持内置 `node:sqlite` |
| npm | 10 或更高 |
| Git | 用于获取源码与更新 |
| 模型服务 | 真实训练需支持 Chat Completions 和结构化输出 |

已使用的开发环境为 Node.js 22.15.0 / npm 10.9.2。首次安装需要能够下载 npm 依赖；OCR、图片与 PDF 处理需要完整的后端运行依赖。

### 1. 获取源码并安装

```sh
git clone https://github.com/ChenFu0604/AI-Defense-Chamber.git defense-chamber
cd defense-chamber
npm ci
```

后续命令均在仓库根目录执行。项目使用 npm workspaces，安装时会自动构建共享包，无需分别进入前后端目录安装。

### 2. 准备后端配置

首次使用可复制模板。已有 `.env` 时保留原文件，按需补充配置。

Windows PowerShell：

```powershell
if (-not (Test-Path apps/server/.env)) {
    Copy-Item apps/server/.env.example apps/server/.env
}
```

Linux / macOS：

```sh
test -f apps/server/.env || cp apps/server/.env.example apps/server/.env
```

后端自动读取 **`apps/server/.env`**，根目录的 `.env` 不会自动生效。不复制模板也可以使用默认端口启动，模型稍后在页面中配置。

### 3. 启动应用

```sh
npm run dev
```

| 服务 | 地址 |
| --- | --- |
| 应用页面 | <http://localhost:5173> |
| 后端健康检查 | <http://127.0.0.1:3001/api/v1/health> |

启动命令同时运行前后端，前端将 `/api` 请求代理给后端。看到页面后，进入“系统设置”配置模型，即可开始真实训练。

项目建档和读取历史不需要模型密钥，但需要后端正常运行。查看模拟示例不会验证真实模型能力。

## 模型与可选服务

### 对话模型：真实训练必需

推荐通过“系统设置 → 模型配置”完成：

1. 填写服务商的 API Base URL 和 API Key。
2. 点击“获取模型”选择模型，也可手动填写服务商的模型标识。
3. 选择结构化输出格式和超时时间，点击“测试连接”。
4. 确认后保存到后端。

API 地址填写基础路径，例如 `https://api.openai.com/v1`；后端会追加 `/chat/completions`，不要重复填写完整接口路径。图片理解还需要模型支持视觉输入。

也可在 `apps/server/.env` 中设置回退配置：

```dotenv
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_API_KEY=填写服务商密钥
OPENAI_MODEL=填写实际模型标识
AI_TIMEOUT_MS=120000
AI_RESPONSE_FORMAT=json_schema
```

若兼容服务不支持严格 JSON Schema，可选择 `json_object`；两种模式仍会校验返回结构和引用。页面保存的配置优先于环境变量，保存后立即用于后续请求；修改 `.env` 需要重启后端。

连接测试与保存是独立操作。连接成功不保证所有业务请求或模型质量均符合预期，缺少配置、超时和无效输出会显示明确错误。

### 向量检索：按需启用

在“系统设置 → 向量模型配置”填写独立地址、密钥和 Embedding 模型，测试后启用并保存。服务需支持 OpenAI 兼容 `/embeddings`，不会自动复用对话模型或密钥。

随后可在“项目详情 → 项目资料库”建立索引，选择关键词、语义或混合检索。不启用向量服务也可以使用关键词检索；语义检索会将查询和需要索引的资料文字发送到配置的向量服务。

### 语音：识别与播报分别配置

在“系统设置 → 语音服务”配置：

- **识别（ASR）**：使用支持 `/audio/transcriptions` 的 OpenAI 兼容服务。
- **播报（TTS）**：支持 OpenAI 兼容语音接口或阿里云 Qwen 语音接口，可为不同评委选声并实际试听。

语音配置与聊天、向量配置相互独立，当前通过页面保存，无语音环境变量回退。音色需匹配提供方和模型；聊天 API 兼容不代表支持音频。

麦克风需要浏览器权限及安全上下文，本机建议使用 `localhost` 或 `127.0.0.1`。录音发送给所配识别服务，转写经用户确认后才进入回答；原始录音不保存到训练历史。

### 数据会发送到哪里？

OCR 和关键词检索在本机后端完成。分析、真实训练与报告会把必要资料和问答发送给已配置的对话模型；语义检索、语音识别和播报分别使用对应服务。请根据资料敏感程度选择服务商。

密钥仅保存于服务端配置，不回传原始密钥，也不写入浏览器 LocalStorage。不要将密钥写进前端代码或 `VITE_*` 环境变量；后端配置文件需由你妥善保护。

## 构建与部署

当前支持本机单用户部署，后端不直接托管前端页面。以下分为构建预览与静态服务部署两种方式。

### 方式一：构建后本地预览

```sh
npm run build
```

构建输出为 `apps/web/dist`、`apps/server/dist` 和 `packages/shared/dist`。若要在预览页面使用设置、语音或旧记录导入，将 `apps/server/.env` 中的来源设置为：

```dotenv
WEB_ORIGIN=http://127.0.0.1:4173
```

在两个终端分别运行：

```sh
# 终端一：后端
npm run start:server
```

```sh
# 终端二：前端构建预览
npm run preview:web
```

访问 <http://127.0.0.1:4173>。Vite preview 适合本地验收，不作为正式静态服务器；改回开发模式时，将 `WEB_ORIGIN` 改回对应开发地址。

### 方式二：本机 Nginx 静态服务

在目标机器安装依赖并构建，保持后端单实例运行：

```sh
npm ci
npm run build
npm run start:server
```

保留服务端运行依赖和共享包，不能只复制 `apps/server/dist`。长期运行可交给系统服务或你已有的进程管理工具；本仓库尚未提供一键安装、Docker 镜像或服务管理脚本。

在 `apps/server/.env` 中设置以下内容并重启后端：

```dotenv
HOST=127.0.0.1
PORT=3001
WEB_ORIGIN=http://127.0.0.1:8080
```

将以下 `server` 段放入已安装 Nginx 的 `http` 配置中，将 `root` 改为实际构建目录。Windows 路径使用正斜杠，例如 `F:/Coding/defense-chamber/apps/web/dist`。

```nginx
server {
    listen 127.0.0.1:8080;
    server_name 127.0.0.1 localhost;

    root /opt/defense-chamber/apps/web/dist;
    index index.html;
    client_max_body_size 24m;

    location /api/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $http_host;
        proxy_read_timeout 320s;
        proxy_send_timeout 320s;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

先检查配置，成功后首次启动 Nginx：

```sh
nginx -t
nginx
```

如果 Nginx 已在运行，则检查配置后重载：

```sh
nginx -t
nginx -s reload
```

访问 <http://127.0.0.1:8080>，健康检查为 <http://127.0.0.1:8080/api/v1/health>。

`proxy_pass` 保留 `/api` 前缀，SPA 回退让项目、报告等页面刷新时仍可打开。静态根目录只指向 `apps/web/dist`，不要暴露项目根目录或 `.data`。指令说明见 [Nginx 静态服务文档](https://nginx.org/en/docs/http/ngx_http_core_module.html#try_files)和[反向代理文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass)。上述配置为部署示例，尚未在独立 Nginx 环境验收。

**公网部署边界：** 当前没有账号、用户数据隔离和多进程会话协调。设置、语音和旧记录导入还会校验本机连接、Host 和来源，换成公网域名不能直接获得完整可用的多人系统。请保持本机使用，公网部署前需补充认证、授权和部署验收。

## 数据与备份

| 内容 | 保存位置 |
| --- | --- |
| 正式项目、版本、画像、会话、问题、回答、报告、改进任务 | 默认 `apps/server/.data/defense-chamber.sqlite` |
| 附件原文件、OCR / RAG 索引、向量缓存 | `apps/server/.data/` 下的对应目录 |
| 页面保存的对话、向量和语音配置 | 后端 `.data` 下的配置文件 |
| 未提交表单、回答草稿与待确认重试信息 | 当前浏览器 LocalStorage |

数据库在首次启动时初始化，不需要另装 SQLite 服务。可在后端 `.env` 中用 `DEFENSE_DATABASE_PATH` 设置数据库绝对路径；这只改变数据库位置，不会一起移动附件和模型配置。

正式记录以服务端已保存数据为准。清理浏览器不会删除数据库中的训练记录，但会丢失未提交草稿；重装或更换机器仍需迁移后端数据。

**备份方法：** 先停止后端，再备份整个 `apps/server/.data`、自定义路径下的数据库，以及单独保护的 `apps/server/.env`。恢复时使用兼容版本，将文件放回对应位置并确认权限后启动。SQLite 使用 WAL，服务运行时不要只复制主 `.sqlite` 文件。当前没有自动备份或一键全量恢复，历史 JSON 导出不能代替完整备份。

**旧版本升级：** 先备份并停止旧服务，再更新、安装和构建。旧服务端 JSON 会在启动时校验迁移，原文件保留；旧浏览器记录通过“检查并导入旧记录”弹窗确认导入。冲突或损坏会明确报错，不会静默覆盖。详见 [SQLite 存储与迁移](docs/sqlite-workspace.md)。

`.env`、`.data` 和 SQLite 文件已加入 Git 忽略规则，仍需避免手动打包或上传其中的密钥与业务资料。

## 常见问题

| 问题 | 处理方法 |
| --- | --- |
| 页面打开，但项目或历史加载失败 | 检查后端是否启动及 `/api/v1/health` 是否可访问，正式记录需要后端在线。 |
| 5173 或 3001 端口被占用 | 释放对应端口；修改后端 `PORT` 时同步调整前端代理，见下方说明。 |
| 模型保存后分析失败 | 核对模型权限、额度、地址、输出格式及网络；连接测试只验证一次短请求。 |
| 修改 `.env` 后仍使用旧模型 | 页面保存的配置优先，请检查“系统设置”，并重启后端使环境变量生效。 |
| 获取模型列表失败 | 部分兼容服务不提供列表，可手动输入实际模型标识后测试。 |
| 设置、语音或旧记录导入返回 403 | 使用本机地址，核对 `WEB_ORIGIN` 与页面地址完全一致，包括协议和端口；不要绕过访问校验。 |
| 图片 / PDF 上传失败 | 图片支持 JPG、PNG、WebP，单张不超过 4 MiB；PDF/TXT 不超过 8 MiB，每组最多 4 个附件。 |
| 提取不完整或 OCR 有误 | PDF 最多 40 页，扫描 OCR 最多 3 页；长文和部分识别会提示截断，表格、手写等需人工核对。 |
| 部署后图片、PDF 或 OCR 无法处理 | 确认已安装完整后端依赖及目标平台所需原生模块，未仅复制 JS 产物。 |
| 语音不可用 | 分别确认 ASR / TTS 配置、音频接口与音色兼容性，以及麦克风权限。 |
| 报告没有综合分或雷达多边形 | 观察不足时属于正常行为，查看原因再针对性训练；旧报告保留原评分并标记覆盖未知。 |
| 重启后看不到旧项目 | 核对是否连接同一后端、数据库路径和数据目录；旧浏览器记录需导入，不要删除原数据来消除错误。 |
| Node 输出 SQLite 实验性提示 | Node 22.15 会显示此提示；若无其他错误，该提示本身不表示数据库启动失败。 |

**自定义后端端口：** 在 `apps/server/.env` 设置 `PORT=3002` 并重启后端，在启动前端的终端同步设置代理。PowerShell 示例：

```powershell
$env:API_PROXY_TARGET = 'http://127.0.0.1:3002'
npm run dev:web
```

`API_PROXY_TARGET` 用于 Vite 开发与预览进程，不会由后端 `.env` 自动传给前端。静态部署则修改 Nginx 的代理目标。

模型访问需要代理时，可在启动环境或后端 `.env` 配置以下变量后重启。请替换为实际代理端口：

```dotenv
HTTPS_PROXY=http://127.0.0.1:7890
HTTP_PROXY=http://127.0.0.1:7890
NO_PROXY=localhost,127.0.0.1,::1
```

## 开发与扩展

前端使用 Vue 3、TypeScript、Vite、Pinia 和 Vue Router；后端使用 Node.js、Express、Zod 和 SQLite；报告图表使用 ECharts，风险地图使用 Vue Flow。

```text
apps/web/         页面、组件、状态管理与前端服务
apps/server/      API、模型调用、文件解析与数据存储
packages/shared/  前后端共享类型、Schema 与业务规则
tests/            集成测试与测试材料
docs/             专题说明与各阶段工程记录
```

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 同时启动前后端开发服务 |
| `npm run dev:web` / `npm run dev:server` | 分别启动前端 / 后端 |
| `npm run typecheck` | 检查共享包、后端和前端类型 |
| `npm test` | 运行 Vitest 单元、组件与 Supertest 接口测试 |
| `npm run build` | 构建所有工作区 |
| `npm run start:server` | 启动已构建的后端 |
| `npm run preview:web` | 预览已构建的前端 |
