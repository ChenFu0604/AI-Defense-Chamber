# 用户体验完善与交付检查

日期：2026-10-22。基于 2B 版本增量改动，不新增生产依赖。

## 交付判断

当前适合本机单用户内部试用和受控演示，尚不建议按面向正式用户的稳定产品交付。本次改善了训练主操作的顺序、等待反馈、结束确认和失败文案，并成功复测此前失败的真实模型议题场景及报告生成。但这些成功样本不等于服务商稳定性、所有角色输出和手机布局均已验收。

| 用户任务 | 当前能力 | 本轮结论与边界 |
| --- | --- | --- |
| 建立项目 | 草稿、表单、附件/OCR、编辑与版本 | 既有回归通过；正式建档仍需完整必填字段，文档主要是提取文字后人工追加 |
| 开始训练 | 自动分析、选择角色/方式/长度、会话保存 | 有准备状态和等待时间；本轮没有重新进行浏览器点击验收 |
| 回答问题 | 当前问题、求助、输入、提交、角色与议题切换 | 主任务前移，辅助操作按需展开，结束前核对未提交内容 |
| 等待与失败 | 防重复、保存原请求、恢复草稿、手动重试 | 新增实际等待计时和长等待说明；外部模型延迟与失败仍需真实样本监测 |
| 查看成果 | 讨论小结、原文依据、真实报告、雷达图、风险地图 | 本次真实报告生成/缓存读取成功；图表数据校验成功，浏览器画布效果未验收 |
| 持续改进 | 历史快照、旧报告复训、评分对比 | 改进任务尚不能跟踪；复训仍沿用旧资料，最新版项目与旧薄弱点联动待实现 |
| 保存与迁移 | 浏览器资料/草稿、后端会话与附件 | 本机单用户存储边界；没有完整工作区备份与跨设备同步 |

## 实际修改

1. **主任务优先**：工作台先显示当前问题、回答反馈、输入与提交。评委切换、训练设置收进可展开卡片；议题依据和完整历史放在主操作之后。历史记录仍可通过原文锚点定位，没有隐藏必要依据。
2. **等待可理解**：分析、训练准备、答辩/求助、报告生成显示“本页已等待”秒数。超过 30 秒解释仍在等待服务，不显示虚假百分比或剩余时间；停止、换请求和组件卸载清理计时器。重新打开页面从本页重新计时，不冒充服务端总耗时。
3. **结束可预期**：增加内联确认。未提交草稿明确不计入记录，已提交失败回答仍保留；结束后草稿可只读查看复制。请求处理中不能结束。结束页不再展示可作答的当前问题或评委切换。
4. **历史文案准确**：只有与服务端 pending 对应的失败回答提示重试；历史/结束消息显示“逐轮评价未完成，记录保留”，不再承诺无法执行的追问重试。最后回答加载文案也不再提前声称已保存。
5. **更正状态反馈**：更正表单在观察到保存记录后才收起并提示成功；失败保留输入，过期 revision 不继续提交。达到题数上限仍可更正状态，但不能再生成新议题问题。
6. **议题选择明确**：模型上下文提供 currentTopicId 和回答充分/换方向时的独立候选分支。提示词要求先评价、再按对应分支选题，消除“推荐当前议题”与“充分后必须离开”之间的表达歧义。上次议题无效的错误在重试中保留供模型参考，成功后清除；不自动额外请求、不放宽校验、不改写回答。
7. **上游故障可区分**：模型不可用错误显示实际 HTTP 状态码，帮助区分网关失败等情况；不回传上游响应正文、密钥或任意诊断头。

## 实际验证

- `npm run typecheck`：通过。开发中调整条件渲染后发现一个不可达的 ended 分支，已移除并重新检查通过。
- `npm run build`：共享包、后端与前端生产构建通过；保留既有 Zod/Rollup 注释位置警告。
- `node node_modules/vitest/vitest.mjs run --no-file-parallelism`：**42 文件、396 项通过**。新增覆盖：候选分支一致性、非法议题重试后只保存一次、上游错误不泄密、结束确认与忙碌保护、更正保存/冲突、计时清理、历史失败文案、工作台顺序与结束草稿可读性。
- 开发中的组件交互测试首次使用内存渲染宿主，因当前 Vitest 的 Vue 模块采用 SSR 编译而失败；现将交互状态放入独立 composable 验证，页面与组件使用真实 SSR 渲染验证。补齐测试 Router 后通过。没有隐藏测试警告、降低业务断言或声称这些是浏览器点击测试。
- 真实模型复测使用此前明确标注的合成项目，沿用已保存模型配置（配置及返回标识为 `gpt-6.1-sol`）。没有读取/上传用户的其他项目资料，没有更改模型设置。
- **议题失败场景复测**：在内存中重建之前商业回答的失败上下文，调用当前真实模型服务；约 **19.3 秒**返回 sufficient + test_boundary，并正确选择 assumptions。结构、原文及议题规则通过。原已结束会话没有被重写；该结果仅作为复测证据保存在忽略目录。
- **真实报告复测**：通过前端 Pinia/API 封装调用生产 Express 接口，约 **57.0 秒**成功生成并持久化报告；GET 约 11ms 返回同一报告。历史归档成功。报告明确标注提示辅助、观察不足和未完成逐轮评价的回答。
- 核对真实报告引用与等权平均；雷达图实际值 `[73,43,54,48,62]`，综合 56。该分数只属于合成训练样本，不是本系统交付评分。ECharts 使用 SVG SSR 输出校验；真实来源风险图 16 节点、6 条共享依据边。
- 此前浏览器工具被本地 URL 安全策略拒绝；本轮没有尝试绕过。**未完成本轮桌面/手机实际浏览器布局、焦点、点击、滚动与控制台验收**，不能据组件测试宣称视觉已验收。

## 正式交付前仍需完成

1. 在可访问的浏览器中验收桌面与 390px 手机完整流程，包括长问题/长回答、展开收起、键盘操作、附件、报告图表和返回路径。
2. 用不同项目类型与回答质量重复跑真实模型场景，记录成功率、耗时、议题拒绝原因；本次成功复测不能证明此前服务商不可用已根治。当前无原始模型失败诊断存档，仍应按最少敏感数据原则设计诊断。
3. 明确交付范围：现有存储适合本机单用户。若要公共站点，需要另行设计身份/访问隔离、数据持久化、备份与恢复，不能直接把本地服务公开当作多用户产品。
4. 优先补齐“报告建议 → 改进任务 → 最新项目版本复训”的持续使用路径。报告的观察不足维度仍必须给估计分，需单独升级评分结构及历史兼容。
5. 完整工作区备份应覆盖项目草稿、版本、会话、报告与附件；现有历史 JSON 不包含所有数据。

本轮没有新增环境变量。实际响应质量仍由所选模型与服务商共同影响；程序校验原文、结构和议题边界不能证明所有语义正确。
