# 本地 RAG 与项目资料库

本文保留 2026-10-23 首版行为与当时验证结果。后续已加入独立 Embedding 配置、语义/混合检索与向量持久化，当前行为见 [向量语义检索记录](rag-semantic.md)。

日期：2026-10-23。本阶段在已有附件、OCR、模型客户端与答辩流程上增量实现检索增强，没有新增生产依赖。

## 用户可见功能

- 项目详情“项目资料库与原文检索”进入 `/projects/:id/knowledge`。资料来自该项目的附件与当前浏览器已保存的改进任务证据；添加材料继续使用项目编辑和任务证据入口。
- 资料库显示待建立索引、可检索、部分可检索、无文字和处理失败，支持逐份重建、可选本地 OCR、刷新状态与失败重试。正在处理时禁用重复操作。
- “搜索原文”仅在本机处理，不调用模型；“基于资料回答”将检索片段发送给已配置的模型。空问题不发送；失败保留问题，切换项目或离开时丢弃旧结果并取消请求。
- 资料问答只接受符合 Zod 的结果，引用 ID 必须属于本次来源，引文必须逐字出现在对应片段。有依据的回答必须有引用；无匹配时返回明确本地提示，未调用模型，不伪装成 AI 回答。
- 参考资料使用共享弹窗，显示文件名、页码/字符范围、原文、OCR 提示与本轮覆盖范围。引用内容通过 Vue 文本插值显示，文件内 HTML 不执行。
- 分析、评委预览、动态答辩、最后一答和报告展示当时保存的参考片段；历史打开使用快照，不重新检索或生成报告。**答辩入口展示的是本轮提供给模型的材料，不声称模型逐条引用或已核验事实。**资料问答的显式引用单独标记。

## 正文、索引与检索

- 前端 `Attachment.text` 继续限制 12000 字，避免改动已有项目/草稿格式与 LocalStorage 容量。新上传的 PDF/TXT/OCR 另在后端 `attachments/:id.source.json` 保存正文、页码、提取方式和覆盖范围。原始文件继续按现有方式保存。
- 每份最多 200000 个字符、PDF 最多 40 页，OCR 仍最多处理 3 个扫描页。未覆盖页、字符上限和无文字状态会明确标记，部分索引不能视为完整资料。OCR 只使用本机已安装组件。
- 老附件没有正文侧文件时，从已校验的原始文件重新解析，不仅索引原有截取预览。显式重建忽略旧解析缓存；原附件元数据与项目版本不被重写。
- 每页分别分块，窗口 900 字符、重叠 150 字符；保留页内字符位置。使用文件内容 SHA-256 和片段位置/内容生成来源 ID，按页分块不会跨页拼接引文。
- 当前检索器使用 Node 的中文分词、英文词项和本地词频/区分度排序，去除明显重叠片段，最多返回 6 条。没有 embedding、向量数据库、语义重排或联网搜索。`TextRetriever` 为后续检索策略保留接口。
- 一般分析与首问额外提供未命中文档的首片段作为概览，明确标记 `overview`；针对实际问题的搜索与资料问答使用 `keyword`，未命中不偷偷用任意段落填充。
- 单次最多检索 32 份不同资料，优先纳入项目附件，超出的数量明确记录。资料库选择任务附件前先去重；超出前端选择上限的任务材料另行提示。图片索引针对 OCR 文字，图表理解仍使用现有视觉模型路径。
- 索引保存于后端附件目录下 `rag-indexes/`，使用版本、内容哈希、结构与校验和检查，原子写入并回读确认。重启复用索引；损坏时保留原文件，提示重建。并发冷索引合并请求，避免重复解析。

## AI 接入与来源边界

- `prepareRagMaterials` 统一为分析、四角色评委预览、动态答辩、最后一答和报告准备材料。追问检索结合最新回答与当前问题，范围包含本场项目、选定复训任务与最近回答的附件，不读取其他项目的文件列表。
- RAG 摘要及片段计入已有上下文长度检查，最新回答继续完整保留。新消息/分析/报告增加可选 `retrieval` 快照，旧记录不要求此字段。
- 项目画像允许引用实际检索片段中的尾部原文，但仍校验文件属于项目；风险图同步定位对应附件。报告评分引用仍只允许本场真实用户回答，材料引用不会自动增加分数。
- 引用证明文字出现在材料里，不证明材料真实性、引文充分支持结论或指标已经外部验证。AI 推断、用户任务完成记录和 OCR 内容都保留未核验边界。
- 服务端对所选附件元信息、原始内容哈希、请求和响应使用校验。文件内指令只作为资料，不授予执行能力；提示词隔离不能保证模型在所有对抗样例中绝对可靠。
- 项目主记录仍在浏览器，后端接受显式项目/附件快照作为本次允许范围。**这不是账号授权或多租户访问控制**，不能把当前本机服务直接公开当作多人资料库。
- 有关索引、解析、模型配置/超时/请求失败均真实报错，没有自动切换模拟回复。读取历史快照不依赖索引仍然存在；“打开原文件”仍需要后端原文件存在。

## 接口

统一前缀 `/api/v1/knowledge`，兼容 `/api/knowledge`。响应沿用 `{success: true, data}`，失败沿用统一错误中间件。

| POST 路径 | 请求（额外字段叠加在 scope 上） | 行为 |
| --- | --- | --- |
| `/library` | `scope` | 读取索引状态，不调用模型 |
| `/index` | `scope + {attachmentId, ocr?}` | 校验资料在本次范围内，从原文件重建 |
| `/search` | `scope + {query}` | 按问题检索，必要时自动建立缺失索引 |
| `/answer` | `scope + {query}` | 检索后调用现有模型，校验原文引用 |

`scope = {project: Project, extraAttachments?: Attachment[]}`。额外资料请求最多 32 份，索引 ID 必须在最终选定文件范围中；请求体上限 2 MiB。检索有 60 秒处理期限，单份重建最多 105 秒，底层 PDF/OCR 仍执行原有解析期限。客户端资料请求最多等待 180 秒；索引写入失败不会返回成功。

## 主要修改位置

- `packages/shared/src/knowledge.ts`：资料范围、索引状态、来源、检索与问答 schema；分析、评委、会话、报告类型增加可选快照。
- `apps/server/src/services/document-source.ts`、`material-text.ts`、`attachment-service.ts`：完整的有界正文和旧附件兼容。
- `apps/server/src/services/rag-search.ts`、`knowledge-service.ts`、`rag-materials.ts`：分块、排序、持久化、引用校验与共用材料准备。
- `apps/server/src/routes/knowledge.ts`、`app.ts`：接口、请求取消和请求大小限制；相关 AI 服务接入检索。
- `apps/web/src/services/knowledge-api.ts`、`composables/useKnowledge.ts`：请求校验、异步隔离与状态。
- `apps/web/src/views/ProjectKnowledgeView.vue`、`components/knowledge/RagSources.vue`、`styles/knowledge.css`：资料库、检索、问答与来源弹窗；相关分析/评委/消息/报告视图复用来源组件。

没有新增环境变量或模型密钥。真实资料问答继续使用现有模型配置，模型兼容和实际回答质量仍需针对所选服务商验证。
