# 第二轮 2B：议题进度与跨评委讨论记忆

日期：2026-10-22。本轮在 2A 的训练设置、求助和即时反馈基础上增量实现，没有新增生产依赖。

## 使用方式与边界

- 从训练准备页创建新训练，工作台显示四项提纲：谁需要这个项目、核心功能怎么实现、项目有什么价值、哪些假设还没验证。这是固定训练提纲，不是模型发现的漏洞，也不是外部已验证的事实。
- 每项显示待讨论、讨论中、已澄清、待补证据或暂缓。状态依据实际回答评价更新，保留来源、原文摘录及关联回答，切换评委后仍向下一位评委提供这些信息。
- 每次进入议题最多生成两道问题。已澄清、暂缓或达到上限的议题不自动重问；离开的待补证据项不自动反复追索。最新回答充分、建议换方向或使用“暂时没有数据”求助后，程序限制自动沿原议题追问。
- 展开“查看议题依据与更正状态”可以核对原文、更正状态及填写原因。更正不调用模型，不修改项目资料或评分。用户明确标记的已澄清、待补证据和暂缓状态不会被后续自动评价覆盖。
- “重新讨论”保留旧问答，并重置本次两题额度；生成新问题会调用所选模型，仍受全场 5/10 题上限和重复问题校验约束。切换议题或评委会把未答题标为跳过；输入草稿保留，并提示核对新问题。
- 没有可继续的议题时，最后一答评价确认保存后允许提前结束，不为凑题数捏造议题。所有议题关闭时直接切换评委会返回明确提示，仍可主动重开、回答当前问题或结束。
- 结束页、报告页与历史页显示保存记录派生的小结：已澄清、待补证据、暂缓、未覆盖及未完成逐轮评价的回答。打开小结不调用模型，不重评历史。
- “已澄清”仅表示本场讨论的状态；用户更正不是事实核验。人工提前关闭但尚未提问的议题仍列在“未覆盖”中，进度与覆盖范围可以不同。

## 接口与存储

现有 `/api` 与 `/api/v1` 前缀均支持以下路径，成功响应仍是 `{success: true, data: DefenseSession}`。

| POST 路径 | 请求 | 行为 |
| --- | --- | --- |
| `/defense/sessions/:id/topic-state` | `requestId, expectedRevision, topicId, status, note` | 更正状态，原因 1～500 字；最多保存 40 次人工更正 |
| `/defense/sessions/:id/topic` | `requestId, questionId, topicId, expectedRevision` | 主动选题/重新讨论，生成下一问 |

`topicId` 为 `needs / solution / value / assumptions`。手动 `status` 可用 `pending / clarified / awaiting_evidence / paused`。

- 状态更正记录审计信息；UUID 幂等重放，内容冲突与过期 revision 返回 409。议题操作与回答、切评委、求助和结束共用会话锁。
- 保存沿用服务端原子文件写入；错误不返回虚假成功。生成失败保留 pending 与回答，刷新后沿用原 requestId、questionId、topicId 和 revision 重试；确认落盘前不会把生成的问题作为成功展示。
- 共享 Zod 结构检查四个议题 ID 唯一、问题归属、回答关联、原文引用及两题预算。模型需要输出有效 topicId；结束时 question 与 topicId 必须同时为 null，且没有可继续议题。
- 每次模型上下文提供各议题最近两条回答摘录与状态，沿用总上下文 32000 字符限制。换评委不重新评价旧回答，但保留其上下文和讨论记忆。
- 只有本轮新建且携带训练设置的会话建立议题记忆。旧会话不回填、不重写，包括已有 2A 记录；缺少新字段时原报告指纹保持兼容。新会话的报告指纹包含议题快照。

## 实际验证

- `npm run typecheck`：共享包、后端、Vue 与前端配置类型检查通过。
- `npm run build`：共享包、后端与前端生产构建通过。存在既有 Zod 注释的 Rollup 警告，不影响本次构建成功。
- `node node_modules/vitest/vitest.mjs run --no-file-parallelism`：最终 **41 个文件、388 项测试通过**，比上一轮增加 17 项。覆盖两题换向、无证据求助、跨评委摘录、更正幂等/冲突、主动重开、模型无效议题、落盘失败、提前结束、未评价回答、报告历史复用、旧会话、模拟标记和前端恢复/只读展示。
- 开发中一次新增定向测试失败：固定测试适配器对同评委的不同议题生成了相同首问，触发重复问题拒绝。已按议题提供不同的测试开场；保留生产重复校验，修复后定向及最终全量测试通过。
- 前端组件验证使用 SSR 渲染，Pinia 验证实际执行状态与草稿恢复。浏览器工具被 URL 安全策略拒绝访问本地页面，本轮未完成浏览器点击、移动端布局和截图验收，也未尝试绕过限制。
- 所有模型链路验收均通过固定测试适配器运行；本地 OCR 回归测试处理实际测试图片/PDF，但没有调用外部真实大模型。

## 当前限制与下一步

- 已接入统一真实模型路径，但本轮验收使用固定测试适配器，没有调用外部真实模型。相关性和通俗引导的实际质量还需配置模型后评估，不能用测试模板证明真实对话质量。
- 程序能限制议题和预算，原文引用能核对来源，但不能证明模型确实理解回答或问题语义正确。去重仍包含文字相似度校验，并非完整语义去重系统。
- 模拟模式采用明确标注的固定问法、反馈和程序状态；每个议题只提供有限问法，反复重开可能触发重复问题错误，不伪造新推理结果。
- 议题固定四项，没有实现 AI 动态拆分、合并或新增议题。更正仅是讨论状态，不会自动修改项目字段，也没有改进任务跟踪。
- 沿用单进程文件存储与进程内锁，不支持多服务器并发；模型成功但落盘失败时，重试可能再次调用模型。
- 本轮未新增环境变量。真实功能仍需服务端模型设置或 `OPENAI_BASE_URL`、`OPENAI_API_KEY`、`OPENAI_MODEL`，以及可选超时/输出格式设置。
- 下一步可增加从讨论小结生成可编辑的改进任务，将修改后的项目版本带入复训；评分未覆盖维度的表达单独设计，不混入本轮。
