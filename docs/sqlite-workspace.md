# SQLite 训练记录与数据迁移

2026-10-25。项目、画像、会话、问题、回答、报告和改进任务改由本机后端 SQLite 保存，服务端返回的已确认记录是正式数据来源。没有引入账号或云端同步，也没有更换答辩状态机、模型协议或评分规则。

## 保存位置和表

默认数据库为 `apps/server/.data/defense-chamber.sqlite`，使用当前 Node.js 22.15+ 的 `node:sqlite`，不新增生产依赖。此 Node 版本会输出 SQLite 实验性警告，未屏蔽。可在 `apps/server/.env` 设置绝对路径 `DEFENSE_DATABASE_PATH`，重启后生效；目录不存在时创建，数据库初始化失败时服务不开始监听。

| 表 | 用途 |
| --- | --- |
| `projects` | 当前项目资料、归档状态、来源、创建/更新时间 |
| `project_versions` | 原项目版本，不覆盖历史会话中的资料快照 |
| `project_analyses` | 已校验的真实或模拟画像，保留各自来源与项目快照 |
| `defense_sessions` | 状态、当前问题/评委、项目与画像快照、重试账本、议题和训练设置 |
| `defense_questions` | 每条真实保存的评委问题、顺序、类型、角色和状态 |
| `defense_answers` | 每条用户回答、关联问题、请求 ID、顺序和状态 |
| `defense_reports` | 每场原报告、来源指纹、报告版本和可空综合分 |
| `improvement_tasks` | 来源报告建议、用户记录的进展、笔记和附件引用 |
| `workspace_operations` / `legacy_imports` | 幂等请求、浏览器导入回执与旧文件迁移指纹 |
| `schema_migrations` | 数据库模式版本；遇到不支持的版本停止，不覆盖原库 |

复杂的会话/报告字段仍保存完整的 schema JSON；问题和回答同时保存真实结构化行。会话、问题和回答在同一事务提交或回滚，读取会核对消息投影与完整快照，不用损坏的一份自动“修复”另一份。查询使用参数绑定，启用外键、WAL、FULL 同步和忙碌等待。模型调用不持有数据库事务。

## 页面行为

- 项目创建、编辑、归档、画像恢复、历史列表、风险图和任务改为服务端 API；网络失败显示错误，不把旧 LocalStorage 当作成功兜底。
- 创建项目使用稳定请求 ID；同请求重试不重复建档，同 ID 不同内容被拒绝。编辑项目和任务携带原 `updatedAt`，过期编辑返回 409；未确认写入可重试，当前内容已等于请求时可安全确认成功。
- 分析成功先保存后返回。开始训练时后端核对当前项目及已保存画像；浏览器传入的快照不能直接替代服务端正式记录。复训保留原会话，可用原资料或当前资料，所选任务须与已保存进展一致。
- 答辩仍通过原 API 防重复、保存失败回答和安全重试；刷新后按会话地址读取。报告继续复用原缓存，不重新调用模型生成不同报告。
- 首页与准备页的最近会话改读服务端；旧记录导入完成后刷新已挂载页面，并丢弃过期读取结果。

LocalStorage 只继续用于未正式提交的项目表单草稿、回答草稿、待确认操作/创建请求和少量界面标记。清理浏览器会丢失这些未提交输入，但不会删除 SQLite 中的正式项目和训练记录。

## 旧 JSON 会话与报告

后端首次启动会校验 `.data/defense-sessions/` 和 `.data/defense-reports/` 的全部旧 JSON，核对文件 ID、报告与会话的来源指纹及原文引用，再在事务中导入。原文件保留，不删除、不改分，也不继续双写。

后续启动按文件指纹账本跳过已迁移且未改变的文件，不用旧 JSON 回退已推进的 SQLite 会话。损坏、同 ID 内容冲突、已迁移文件后来改变时明确停止，保留原文件和数据库；需要核对冲突后再启动，不能通过删除原记录制造成功。升级前应停止旧服务，避免旧进程继续写 JSON。

## 旧浏览器记录

后端不能直接读取浏览器 LocalStorage。页面检测到旧正式记录后提供“检查并导入旧记录”弹窗，列出项目、画像、会话、报告和任务数量。用户确认后仅发到当前本机后端，不调用外部模型。

导入前分别校验旧数据；读取损坏不会覆盖或删除原字节。预览后源数据变化需要重新检查。同一批次复用请求 ID，后端事务成功后保存回执，浏览器标记本身不充当迁移成功证据。更换后端或数据库不存在回执时仍能重新导入。

当前浏览器中的项目主记录与历史快照分开处理；服务器已有正式项目、会话或任务与导入内容冲突时，整包导入返回 409 并回滚，不自动选择一份覆盖另一份。界面保留原记录和重试入口。附件须在当前后端真实存在且元数据匹配，原始文件不会通过 JSON 导入。

当前保守版不提供逐项冲突合并器或通用备份导入；409 冲突需人工核对。损坏数据不会被静默跳过，导入成功也不意味着浏览器提供的内容成为不可篡改的外部证据。

## API

统一前缀 `/api/v1`，继续兼容 `/api`；响应沿用 `{success:true,data:...}` 和现有错误结构。

| 方法/路径 | 数据 |
| --- | --- |
| `GET /projects` | 项目、版本与归档状态 |
| `POST /projects` | `{requestId,input}`，返回保存后的项目 |
| `GET /projects/:id` | 当前项目 |
| `PUT /projects/:id` | `{expectedUpdatedAt,input}` |
| `PATCH /projects/:id/archive` | `{archived}` |
| `GET /projects/:id/analyses` | 已保存的画像列表 |
| `POST /projects/analyze` | 原分析协议，先持久化再成功返回 |
| `GET /history` | 服务端项目、画像、完整会话和原报告快照 |
| `GET /improvements` | 已保存任务 |
| `POST /improvements` | `{sourceSessionId,improvementIndex}`，从原报告创建任务 |
| `PUT /improvements/:id` | `{expectedUpdatedAt,update}` |
| `POST /workspace/import` | 校验后的旧浏览器记录，24 MiB 上限，仅本机来源及专用请求头可访问 |
| `GET /workspace/import/:id` | 服务端迁移回执，未导入返回 `null` |

原会话、问题、回答、结束、求助、复训和报告接口保持不变。测试注入的业务服务可单独隔离验证，生产默认使用 SQLite 及服务端项目/画像核验。

## 备份和当前限制

附件、OCR/向量索引和模型配置仍保存在 `.data` 文件中，SQLite 不包含附件原文件。历史和任务 JSON 导出读取最新后端快照，仍不是整个工作区备份。完整迁移机器需在停止服务后备份数据库及必要的附件/索引目录，并妥善保护独立密钥配置；不要只在 WAL 活跃时拷贝主数据库文件。

本阶段仍面向本机单用户。没有用户身份、数据归属权限、跨设备云同步、数据库加密、自动备份、列表分页或跨进程答辩状态锁；不能据此直接开放公网。同步 SQLite 适用于当前有界事务，大型资料库和大量会话需后续分页与容量策略。

实现参考 [Node.js 22.15 SQLite 官方文档](https://nodejs.org/download/release/v22.15.0/docs/api/sqlite.html)。当前环境实际验证 `DatabaseSync` 可用，不依赖该版本不存在的异步备份 API。
