# 第八阶段：历史记录与二次训练

## 页面与流程

- `/history`：项目档案、每场答辩的项目类型/时间/状态/本场评分、最近项目评分、旧入口只读同步、备份导出和对比入口。
- `/history/projects/:id`：保存的项目资料和分析版本。
- `/history/:id`：当时项目/画像快照、完整消息、出现过的评委、原报告、风险与建议。直接读取 LocalStorage，不调用模型；全局布局健康检查独立于历史内容。
- `/history/:id/train`：展示原报告薄弱点与改进任务，选择首位评委，确认后创建新会话。原项目、会话、消息和报告不覆盖。
- `/history/compare`：选择同一项目两场不同的已保存报告，对比综合分与全部五个维度；差值为“对比场次 − 基准场次”，支持正数、负数及零。只使用归档分数，不补造变化。

项目详情仍使用当前浏览器主项目；历史档案和会话快照保存当时版本，不因当前项目资料改变而重写。针对历史弱点的新训练沿用原项目与画像；如需更新项目资料，可从项目准备流程开始另一场训练。

## LocalStorage 历史归档

`packages/shared/src/history.ts` 定义统一 HistoryArchive / HistoryEntry、Zod 校验及对比计算。`apps/web/src/services/history-storage.ts` 统一处理归档读写与创建请求恢复；组件不直接操作 LocalStorage。历史 key 为 `defense-chamber.history.v1`，记录独立项目/分析版本及包含完整会话、原报告和归档时间的条目。项目创建、分析成功、会话状态更新、报告读取/生成成功时自动补存。

每个写入前校验旧归档及新数据，整体序列化后一次写入并回读确认。3 MiB 是本归档主动设置的 UTF-16 估算上限，不代表浏览器剩余容量；写入受限或浏览器总配额不足时明确提示，不驱逐旧记录，不把归档失败说成成功。后端原文件存储和本地草稿继续保留，归档失败不抹掉实际已保存的后端结果。项目/分析及会话主记录仍沿用原存储；归档是本地历史副本，没有引入数据库或账号。

已带报告的快照/报告发生变化时拒绝自动覆盖旧历史。源会话与报告的项目 ID、会话 ID、回答原文引用必须一致。版本 1 缺字段、损坏 JSON、重复 ID 或未知版本报错并保护原数据；支持版本 0 `{version:0,entries:[完整 HistoryEntry]}` 读取迁移到版本 1，读取时不重写原字节。旧会话中缺少可选 training 字段保持兼容。导出直接保存历史 key 原始文本，因此损坏数据也可以先备份。

对于本功能上线前的数据，历史页面合并当前项目、当前分析和旧的最近会话入口。可以显式“补存已有项目与画像”，或对旧入口执行“只读同步历史记录”。同步仅 GET 原会话和已有报告；REPORT_NOT_FOUND 明确说明尚无报告，网络/损坏等其他失败不当作缺报告。旧索引只保留过往设计中的最近 20 个入口，不保证发现浏览器从未记录过的后端会话。

创建/二次训练请求在发出前，将其原始 requestId 和输入保存到 `defense-chamber.pending-create.v1`。网络异常或刷新后，同资料与角色的重试复用相同 ID；对创建输入先做 schema 标准化，避免字段顺序不同误判为新请求。确认新会话 ID/训练来源后清理待创建标记。历史列表提供待确认会话读取及原准备页恢复入口。

不归档模型配置、API 密钥、Authorization 或服务端环境变量。用户输入的项目与回答仍属于本地数据，不能依靠浏览器存储代替备份；更换浏览器/设备或清除数据后需要重新同步后端已有会话。当前提供导出，不提供自动清理、备份导入、跨设备同步或加密存储。

## 二次训练后端

新增 `POST /api/v1/defense/sessions/:id/retrain`（兼容 `/api`），请求 `{requestId,judgeId}`，返回 201 `{success:true,data:DefenseSession}`。后端读取原会话及已保存评分报告，要求真实模式、已结束、报告来源指纹与引用吻合。缺报告或来源冲突明确失败，不重新生成旧报告。

新会话采用新的请求 ID，保留原始项目/画像快照及 `training:{sourceSessionId,sourceReportId,focus}`；后端从原报告抽取最多 2 项薄弱点和 2 项改进任务，每项最多 1500 字。创建不调用模型。后续统一上下文和评委 System Prompt 明确使用这些历史重点，但不能预设新表现，仍需依本轮回答分析。相同创建 ID 重放返回同一会话，内容或角色不一致时拒绝，不能复用原会话 ID。

训练结束后使用已有报告生成流程为**新会话**生成新报告，并自动归档。原报告始终保留，旧报告不会因为历史重开或二次训练自动被重新评分。新模型调用仍通过系统设置里的统一服务，不伪装为模拟结果；本阶段模型联调测试均使用明确的固定测试响应。

## 验证与当前限制

测试覆盖项目新建后归档、完整记录读取与刷新恢复、历史原报告不变、版本迁移/缺字段/损坏保护、容量与配额失败、实际归档评分对比、只读同步、普通创建和二次训练请求刷新重试、训练源校验/幂等/HTTP 参数、新会话完成后生成自己的报告且保留旧报告。浏览器使用独立端口与固定测试数据验证列表、历史重开、刷新、维度差值、创建新训练及训练重点/首问与草稿恢复，不调用真实模型或修改用户数据。

实际执行：`npm test` 全量 30 个文件、302 项通过（本阶段新增 22 项）。`npm run typecheck` 与 `npm run build` 均通过，构建保留两条既有 Zod 注释警告；历史页面按路由分包。浏览器验证桌面和 390px 窄屏评分对比无横向溢出。修复了二次训练返回新会话 ID 时客户端误用旧 ID 校验，以及刷新后的创建输入字段顺序差异导致无法复用请求 ID，并各有回归测试。

评分是 AI 主观训练评价，题目、模型、回答数量、项目版本与答辩难度均可能影响分数；页面不将变化等同为客观能力提升。归档不保存独立的风险图副本，历史风险从当时画像、回答与报告确定性恢复。二次训练需要后端保留原会话和原报告；仅本地有离线副本而后端丢失时可回看，但不能绕过后端来源校验创建针对性训练。
