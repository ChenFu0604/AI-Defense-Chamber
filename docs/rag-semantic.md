# 向量语义检索与混合 RAG

日期：2026-10-24。在已有原文索引、资料库、引用校验及 AI 服务上增量实现，没有增加生产依赖。

## 使用方式

1. 系统设置 → 向量模型配置：填写支持 Embeddings 的 API Base URL、模型 ID 和独立密钥。默认关闭，不将已有聊天密钥转发给其他地址。
2. “测试向量连接”只发送固定短文本，验证真实响应结构、维度与非零有限向量；不会保存表单或使用项目资料。测试成功不能代表资料召回质量已验收。
3. 勾选启用并保存。配置仅保存在后端 `.data/embedding-config.json`，公开接口只返回 `hasApiKey`。也可填写 `.env.example` 中的独立 `EMBEDDING_*` 变量；后端已保存配置优先。
4. 项目详情 → 项目资料库：可以逐份建立原文或向量索引，再选择关键词、语义或混合检索。缺少有效向量的资料在语义请求时会自动分批索引，已有缓存复用。
5. 配置启用后，项目分析、评委预览、动态答辩、最后一答与报告的共用材料准备默认使用混合检索。资料库界面默认仍是关键词，发送明确的模式参数。历史打开继续读取当时保存的片段，不重新请求 Embedding。

语义/混合检索会把问题与需要索引的资料文字发送给配置的向量服务。关键词搜索、原文索引和 OCR 在本机处理；“基于资料回答”另将命中原文发送给聊天模型。界面分别说明这些行为。

## 实现

- 独立 OpenAI 兼容 `POST /embeddings` 客户端，按照 [OpenAI Docs 的 Embeddings 接口](https://developers.openai.com/api/reference/resources/embeddings/methods/create) 发送 `encoding_format:float`；可选 `dimensions`，不假定聊天模型支持向量。
- 每批最多 32 个非空文本，每个不超过 900 字符。校验响应数量、完整且唯一的原始 index、索引重排、有限非零值、相同维度、配置维度及返回模型；最多 4096 维、8 MiB 响应。网络失败、认证、限流、超时、取消和格式错误有明确错误，不接受占位向量或模拟输出。
- 使用现有模型传输层支持后端代理；不跟随重定向转发密钥。模型设置接口复用本机连接、Host、可信 Origin、专用请求头保护。
- 分块与关键词算法沿用首版。语义分数采用归一化向量的余弦相似度，默认阈值 0.35，可在配置中调整 0～1。阈值只过滤语义候选，不是证据可靠性或事实置信度。
- 混合检索对关键词排序和通过阈值的语义排序进行 Reciprocal Rank Fusion，常数为 60；去除明显重叠片段，最多返回 6 条。关键词命中不因语义阈值而直接丢弃。一般分析/首问可额外补充文档首片段，使用 `overviewIncluded` 明示，不能当作问题相关性已确认。
- 向量保存在 `attachments/rag-indexes/vectors/:attachmentId.json`。文件包括版本、配置指纹、分块内容指纹、模型、实际维度、归一化向量、片段 ID 和更新时间，外层有校验和；原子写入并回读确认。没有密钥、查询向量或查询历史。
- 配置指纹包含 API 地址、请求模型及请求维度，资料指纹包含片段 ID 和文字哈希。内容或配置变更显示需重建；检索会先建立新向量。不同文档/问题返回模型或实际维度不同会报错，不会混合比较；索引损坏须明确重建，仍可独立使用关键词搜索。
- 冷索引任务按文件共享；worker 独立管理取消，每条调用可单独退出，所有调用离开后才取消 worker，避免一个页面取消影响其他请求。原文索引同步修复此问题。取消不会将原文标记为解析失败。
- 单次最多 1200 个非空向量片段；超限明确返回 413，可缩小材料范围或改用关键词。每份索引最多 400 个片段、64 MiB，向量索引/检索总期限 150 秒。缓存保存成功的文件在后续重试中复用；不静默丢弃未处理资料。
- 检索快照新增 `semantic/hybrid` 策略与 `embedding:{model,dimensions,minSimilarity}`；文档增加可选 `vector` 状态。旧记录、原文来源 ID、页码、字符位置和引用校验保持兼容。
- 未启用时自动 AI 路径继续关键词检索。显式语义请求缺配置报 503；主动启用但配置残缺、上游失败、损坏或维度不兼容不静默降级。语义无匹配仍可能已调用 Embedding，但不调用回答模型，界面明确区分。

## 修改位置

- `packages/shared/src/embeddings.ts`、`knowledge.ts`：统一配置、检索模式、向量状态和结果校验。
- 后端 `config/embedding*.ts`、`services/embedding-client.ts`、`embedding-settings-service.ts`：独立配置、受控传输、密钥保护与持久化。
- 后端 `services/vector-search.ts`、`shared-work.ts`、`knowledge-service.ts`：向量缓存、精确检索、混合排序、取消隔离与既有 RAG 集成；路由传递检索模式。
- 前端 `EmbeddingConfigCard.vue`、`useEmbeddingSettings.ts`、`embedding-settings-api.ts`：配置卡片、连接测试、提交/失败/取消状态。
- 前端 `ProjectKnowledgeView.vue`、`useKnowledge.ts`、`knowledge-api.ts`、`RagSources.vue`：模式选择、独立索引、模型/状态/来源说明及过期响应隔离。
- 测试增加 Embedding 客户端/设置、向量检索集成与前端交互覆盖；默认配置与环境读取隔离真实用户凭据。

本轮使用合成资料、临时目录、真实 HTTP 协议和受控响应测试召回机制。受控向量明确编码测试含义，不能作为服务商中文语义质量的测量。未复用用户聊天密钥或调用用户真实 Embedding 服务；尚需在系统设置配置所选服务并用实际项目资料验收。

仍是本机单用户的有界精确向量检索，没有向量数据库、近似索引、独立重排模型、全文后台队列或多 Agent 工具调度。同一地址/模型名称在上游实际换权重无法自动发现，应主动重建；更换密钥但地址/模型/维度不变会复用现有向量。语义阈值需要根据服务商和资料样例调优；无法保证每条结果充分支持结论。原文最多 20 万字符、40 页，扫描 OCR 最多 3 页，图片语义仍限于 OCR 文字。

浏览器实屏验收未执行。组件 SSR、HTTP 和状态测试不代表桌面/移动端视觉或真实模型质量已验收。
