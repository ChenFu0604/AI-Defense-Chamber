# 评分观察覆盖与历史兼容

2026-10-25。本轮把“观察不足”从理由中的提示改成独立的数据状态，沿用现有报告接口、评分范围和五维等权规则。

## 用户可见行为

- 每个新报告维度都有 `assessed`（已评估）或 `insufficient`（观察不足）状态。已评估必须包含 0～100 整数分、理由及至少一处真实回答引用；观察不足的分数必须为 `null`，理由说明缺少什么观察，允许没有相关引用。
- 回答已涉及某维度但论证薄弱、证据差，可以给低分；没有讨论、只有未回答的问题或无法形成判断时，不用估计分代替观察。真实 0 分仍是已评估分数，不等于未知。
- 只有五个维度全部已评估时计算综合分：各占 20%，最终均分保留一位小数。有任意观察不足时，综合分为 `null`；不会按剩余维度重算权重，也不按零分拉低成绩。
- 报告显示“已评估 n / 5”，每个不足维度显示“未充分评估”与原因，不显示分数或进度条。部分覆盖时雷达图保留五个坐标轴和真实分数列表，不绘制评分多边形，避免把缺少数据连成完整能力画像。
- 历史列表保留部分报告入口，明确暂不计算综合分。历史对比只对两场均已评估的相同维度计算变化；缺分不表示退步，覆盖不足不计算综合变化。

## 版本、接口与存储

- 新生成报告为 `version: 2`。`POST /api/v1/defense/sessions/:id/report` 和 `GET` 路径不变，兼容 `/api` 前缀；`overallScore` 现在允许为 `null`。
- 模型输出 schema 要求五个维度完整存在，每维必须显式提供状态；状态和分数不一致、缺少理由、已评估却没有引用等输出直接拒绝。模型不输出综合分，由业务代码计算并再次校验。
- 旧 `version: 1` 报告仍按原结构读取，保留原分和原文，标注“旧版评分，观察覆盖未记录”。不根据旧理由文字猜测覆盖，不自动重新调用模型或覆盖旧结果。
- 旧版之间仍可回顾原有差值，但页面说明覆盖未知；旧版与新版不计算变化，避免把未知覆盖当作已评估。同一历史归档可同时容纳两种版本，无须改写浏览器存储键或执行破坏性迁移。
- 已保存报告继续复用缓存。查看旧报告不会升级成新版；希望使用新规则时，需要完成新的训练并生成新的报告。更新部署需同时更新共享包、后端和前端，旧前端不兼容新版报告格式。

## 判断边界

模型提示词要求依据真实问答判断覆盖，不能按评委身份或题数认定已完成五维评价。报告上下文新增问题 ID、类型和实际前一回答关联，帮助核对是否发生有效追问；这种关联本身不是追问质量证明。

未发生有效追问及对应回答时，提示词要求临场应变为观察不足。文字记录中的应对评价不代表测量了真实反应速度、语速、停顿、情绪或口语表现。

程序校验结构、状态/分数一致性、综合分、引用存在性和逐字原文；维度是否被充分观察、引用是否足以支撑语义判断，仍依赖模型及后续效果验收。没有用题数阈值或角色名称自动补认观察，也没有伪造分数。

模型维度使用普通互斥联合，实际发送的 JSON Schema 为嵌套 `anyOf`，根节点保持对象，所有状态字段必填。避免 Zod 判别联合生成的 `oneOf` 引入兼容问题；两种现有输出模式均增加实际请求体测试。依据 [OpenAI Docs 的结构化输出说明](https://developers.openai.com/api/docs/guides/structured-outputs)，这不代表已验证所有兼容服务商的实际支持情况。
