# 第六阶段：评分报告与能力雷达图

## 实现

沿用 Vue 3、Pinia、Express、TypeScript、Zod、统一 AIClient 和本地文件存储。新增 ECharts 6.1，按需加载 RadarChart、RadarComponent、AriaComponent 和 SVGRenderer，报告未成功生成时不加载图表模块。

报告包含五维评分（0～100 整数）、各维度理由与回答原文引用、整体评价、样本限制、优点、薄弱点、证据缺口、优先问题、可执行改进任务与完成标准。综合分由 `calculateOverallScore` 统一取五维等权平均（各 20%），只对最终结果四舍五入到一位小数。模型输出不允许带综合分；历史报告也校验综合分与分项一致。

只允许已结束的真实模式会话生成评分报告，至少需要一条已提交回答。结束前逐轮生成失败但已保存的用户回答也会纳入，并明确其状态。未作答问题不计为用户回答。不对模拟会话生成真实评分或固定模拟雷达图，原有问答与逐轮反馈保持可读。

所有报告依据必须关联实际用户消息 ID，并逐字匹配相应回答；不能引用评委问题或项目资料充当回答证据。模型调用前提取项目、必要画像背景及全部已保存问答，序列化上限 180000 字符，超限明确失败，避免静默丢弃回答。模型评分是主观训练建议，页面展示样本限制；未充分观察的维度要求在理由中说明。

## API

支持 `/api`、`/api/v1` 两个前缀：

- `POST /defense/sessions/:id/report`：无请求体，从服务端会话读取资料、生成、校验并保存，返回 `{success:true,data:DefenseReport}`。
- `GET /defense/sessions/:id/report`：读取已保存报告；没有报告返回 404 `REPORT_NOT_FOUND`，不会触发模型。

同一服务实例对同会话的并发生成请求复用同一个 Promise。成功结果缓存于 `apps/server/.data/defense-reports/<sessionId>.json`，使用临时文件和原子改名保存；重启后直接读取。来源指纹包含项目、画像、会话模式、结束时间与全部消息，来源不一致、文件损坏时明确报错并保护原文件。模型失败和保存失败不会显示成功，也不会自动降级或自动重试模型请求。

主要错误：`REPORT_SESSION_NOT_ENDED`（409）、`REPORT_EMPTY_SESSION`（422）、`REPORT_DEMO_SESSION`（422）、`REPORT_INVALID_HISTORY`（422）、`REPORT_INVALID_EVIDENCE`（502）、`REPORT_CONTEXT_TOO_LARGE`（413）、`REPORT_SOURCE_MISMATCH`（409）、`REPORT_STORAGE_CORRUPT` / `REPORT_STORAGE_ERROR`（500）。模型未配置、认证、网络、超时、无效输出错误复用统一 AIClient。

## 页面与状态

现有 `/defense/sessions/:id/report` 页面先读取会话和历史报告。缺报告时明确提供“生成评分报告”，并说明将向配置的模型发送问答。支持加载、生成、成功、缺数据、失败重试和重新读取；浏览器超时提示先读历史，后端可继续完成保存。Pinia 防止同页重复提交，切换会话/离页取消浏览器等待并忽略迟到响应。ECharts 数据直接取同一份五维评分，支持数据更新、ResizeObserver、自适应重绘和卸载销毁。报告引用可定位到下方原始回答。

## 验证与限制

自动化测试覆盖综合分、非法评分/缺字段、上下文、空/未结束/模拟会话、模型无效输出和失败、超时、引用不匹配、并发去重、保存失败、来源变化、文件重启读取/损坏/路径保护、HTTP 两个前缀、前端状态与重试/历史/迟到响应，以及实际 ECharts SVG 雷达图渲染和数据更新。浏览器验收使用独立端口和明确标注的固定测试样例，不写用户数据、不调用真实模型。

实际执行：`npm test` 全量 24 个文件、261 项通过（本阶段新增 30 项）；`npm run typecheck` 与 `npm run build` 均通过。构建保留既有的两条 Zod 注释警告。浏览器验证缺报告入口、生成中、生成成功、刷新直接读历史、雷达图 SVG 与回答引用定位；当前视口无横向溢出。

真实报告入口已连接统一模型服务，但本阶段不以测试样例声称已验证真实服务商生成质量。评分量表尚未经外部标定；跨进程/多实例锁、数据库事务、强制重新生成、报告导出与多场能力趋势不在本阶段范围内。当前保证单个 Node 服务实例内去重与本地文件持久化。
